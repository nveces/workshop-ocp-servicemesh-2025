Warning: Distributed tracing plarform (Jaeger)

Source: https://docs.redhat.com/en/documentation/openshift_container_platform/4.18/html/distributed_tracing/distributed-tracing-platform-jaeger#dist-tracing-jaeger-installing

https://docs.redhat.com/en/documentation/openshift_container_platform/4.18/html/distributed_tracing/distributed-tracing-platform-tempo

The Red Hat OpenShift distributed tracing platform (Jaeger) is a deprecated feature.
Deprecated functionality is still included in OpenShift Container Platform and continues to be supported; however, it will be removed in a future release of this product and is not recommended for new deployments.
Users must migrate to the Tempo Operator and the Red Hat build of OpenTelemetry for distributed tracing collection and storage.

The Tempo operator supports for storing Tempo data:

  • OpenShift Data Foundation,

  • AWS S3,

  • Azure,

  • GCS

  • and Minio.

Lab 1 - Install Tempo Operator

Naturally, we could install operators using the OpenShift Web Console, but for this tutorial, we will use the CLI.

Navigate to the project folder in your system after repository download for completing all tasks included in this tutorial:

cd ocp-servicemesh-labs-2025/lab-00/tempo

Create the openshift-tempo-operator namespace:

oc apply -f 10-ns-tempo-operator.yaml

Create an Operator group:

oc apply -f 20-operatorgroup-tempo.yaml

Create the subscription:

oc apply -f 30-sub-tempo.yaml
How to know the current version of an operator.

Before to create subscrption, if you want to know the specific channel name, currentCSV, and other information about this operator, run the following command:

oc get packagemanifest tempo-product -o yaml

We highlight the lines:

.../...
status:
  catalogSource: redhat-operators
  catalogSourceDisplayName: Red Hat Operators
  catalogSourceNamespace: openshift-marketplace
  catalogSourcePublisher: Red Hat
  channels:
  - currentCSV: tempo-operator.v0.15.4-1
.../...

Check the Operator status by running the following command:

oc get csv -n openshift-tempo-operator
oc get csv -n openshift-tempo-operator | grep tempo
tempo-operator.v0.15.4-1     Tempo Operator        0.15.4-1   tempo-operator.v0.15.3-1       Succeeded

Lab 3 - Creating a TempoStack

Create the tempo-observability namespace:

oc apply -f 11-ns-tempo-observability.yaml

Create the Object Storage bucket:

oc apply -f 40-objectbucketclaim-tempo.yaml
Figure 1. Check the Object Storage bucket status: Bound
This step creates also the tempo-bucket-odf secret in the tempo-observability namespace. This secret contains the credentials to access the bucket.

Create the tempostack-dev-s3 secret for the TempoStack on the tempo-observability namespace:

 oc -n tempo-observability create secret generic tempostack-dev-s3 \   (1)
  --from-literal=bucket="<tempo_bucket>" \                             (2)
  --from-literal=endpoint="<bucket_endpoint>" \                        (3)
  --from-literal=access_key_id="<bucket_access_key>" \                 (4)
  --from-literal=access_key_secret="<bucket_secret_key>"               (5)
1 Name of the secret.
2 Name of the bucket. From the tempo-bucket-odf secret.
3 Endpoint of the bucket.
4 Access key ID. From the tempo-bucket-odf secret, the access_key_id key.
5 Access key secret. From the tempo-bucket-odf secret, the access_key_secret key.

From the tempo-bucket-odf secret created when we did create the objectbucket claim in the previous step, you can get the values for the bucket name, endpoint, access key ID, and access key secret.

  • AWS_ACCESS_KEY_ID

  • AWS_SECRET_ACCESS_KEY

Get the AWS_ACCESS_KEY_ID key value from the tempo-bucket-odf secret:

oc -n tempo-observability get secret tempo-bucket-odf -o jsonpath='{.data.AWS_ACCESS_KEY_ID}'  | base64 --decode

Get the AWS_SECRET_ACCESS_KEY key value from the tempo-bucket-odf secret:

oc -n tempo-observability get secret tempo-bucket-odf -o jsonpath='{.data.AWS_SECRET_ACCESS_KEY}'  | base64 --decode
oc -n tempo-observability get ObjectBucketClaim tempo-bucket-odf -o jsonpath='{.spec.bucketName}'

For example, if you have the following values:

 oc -n tempo-observability create secret generic tempostack-dev-s3 \
  --from-literal=bucket="$(oc -n tempo-observability get ObjectBucketClaim tempo-bucket-odf -o jsonpath='{.spec.bucketName}')" \
  --from-literal=endpoint="s3.openshift-storage.svc:443" \
  --from-literal=access_key_id="$(oc -n tempo-observability get secret tempo-bucket-odf -o jsonpath='{.data.AWS_ACCESS_KEY_ID}'  | base64 --decode)" \
  --from-literal=access_key_secret="$(oc -n tempo-observability get secret tempo-bucket-odf -o jsonpath='{.data.AWS_SECRET_ACCESS_KEY}'  | base64 --decode)"

Create the TempoStack object:

oc apply -f 50-tempostack-tempo.yaml

We highlight:

To enable metrics of a TempoStack instance, set the spec.observability.metrics.createServiceMonitors field to true

.../...
 observability:
    metrics:
      createServiceMonitors: true
.../...

To enable alerts for a TempoStack instance, set the spec.observability.metrics.createPrometheusRules field to true

.../...
 observability:
    metrics:
      createPrometheusRules: true
.../...
